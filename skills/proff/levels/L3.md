# L3 — the full lesson: a detailed write-up and an interactive deck

L3 is the deep version. The user will often branch into follow-up questions from it, so **leave nothing important out.** Take the time. Exams and reviewers ask from angles the user did not see coming; prepare them for those angles.

You write the chat text and a small JSON spec. The scripts turn the spec into the deck. **Never write or read the CSS or JS.**
Paths below are relative to this skill's folder (the folder with `SKILL.md`).

## 1. Plan the visuals first
List the parts of the topic that a picture explains better than words. Then pick **as many visuals as the topic needs** (usually 2–6; one is fine for a small topic):
- a thing that changes over time or in a sequence (a pathogen binds, then enters; a pipeline runs) → `svg` slide with `steps`;
- a calculation → `calc` slide, one line per step;
- a shape or a spread (a distribution, a dose curve, a tree) → `svg` slide;
- a process with 3–5 named stages and no geometry → `flow` slide;
- a parameter whose value changes the answer → `sim` slide.
Do not draw decoration. Each visual answers one question the reader would ask.

## 2. The chat write-up (STE; long is fine, padding is not)
Use these sections in order. Skip a section only if it truly does not apply.
1. **Answer** — 2–4 sentences.
2. **What you need first** — the 2–5 prerequisite ideas, each one line: `term — plain meaning`.
3. **How it works** — the mechanism step by step. Add a diagram wherever it helps (Mermaid or a text diagram, as in `levels/L2.md`). Several diagrams are fine.
4. **Worked example** — real numbers, every step shown, units kept.
5. **Where it breaks** — assumptions and the cases where the method or idea fails.
6. **Exam angles** — 4–6 questions asked in an unexpected way, each with a short answer. Cover the angles that fit:
   - reversed (given the result, find the cause);
   - edge case (n = 1, zero, a ceiling, a rare event);
   - numbers changed (double one input: what happens?);
   - confusable (two terms or methods that are mixed up);
   - design or data reading (a figure, a table, an experiment to judge);
   - "why not X?" (the obvious alternative and why it is wrong or worse).
7. **Do not confuse** — a small table: term · means · not the same as.
8. **Read next** — 3–5 search terms, each with what it will teach. Name a textbook or paper only if you are certain it exists, and mark it "(from memory, not opened)". Give details (DOI, page, figure) only for sources opened this session.
9. **Claim block** if it is science (see `SKILL.md`).
Then the deck path and the offer line.

## 3. The deck
1. Write `spec.json` in the user's working folder, or a `proff/<topic>/` folder there. **10–20 slides**, chosen for the topic.
2. Render and check:
   ```
   python3 scripts/render.py spec.json -o deck.html
   python3 scripts/snap.py deck.html      # needs playwright; skip if missing
   ```
   `snap.py` prints `WARN slide k ...` for text that spills, is clipped, or leaves its diagram. Fix the spec, re-render. Look at `snaps/sheet.png` once, and at each `svg` slide.
3. Tell the user the path. Arrow keys or space step through builds and slides; Down/Up jump slides. `--layout page` gives one scrolling page.
4. Offer: `→ quiz me · guide me · image` (an image is made only when the user asks; see `ref/image.md`).

## Spec
```json
{"title": "The Bootstrap", "palette": "aurora", "slides": [ ... ]}
```
Text fields accept `**bold**`, `*italic*`, `` `code` ``, blank line = new paragraph, `- ` lines = list.
Any slide may add `title`, `eyebrow` (small label), `hand` (a short handwritten aside, lowercase).

| type | fields | use for |
|---|---|---|
| `title` | `title`, `subtitle`, `hook` | slide 1 |
| `predict` | `q`, `options[]`, `answer` (0-based index), `why` | predict before teaching |
| `notes` | `notes[]` of `{h, t, icon}` | 2–4 prerequisites or key terms |
| `text` | `t` | the problem, a definition (≤ 70 words) |
| `statement` | `text`, `color` | one big sentence |
| `svg` | `svg`, optional `steps[]`, optional `notes[]` | a drawn diagram; with `steps` it builds up (see `ref/svg.md`) |
| `calc` | `given`, `lines[]` of `{expr, note, result}` | a calculation, one line per step; `result: true` boxes the answer |
| `flow` | `steps[]` of `{h, t}` | a named process in 3–5 stages |
| `sim` | `controls[]`, `js`, `text`, `reseed` | a parameter you can move |
| `compare` | `a {h,t}`, `b {h,t}`, `vs` | works vs fails, A vs B |
| `angles` | `cards[]` of `{tag, q, a}` | exam angles as flip cards (≤ 4 per slide) |
| `quiz` | `cards[]` of `{q, a}` | 2–3 recall cards |
| `takeaway` | `points[]`, `caveat`, `next` | last slide; `next` = what to read or search |
| `image` | `src`, `caption`, `notes[]` | only if the user asked for an image |

A typical order: title → predict → notes → text → svg/flow scenes → calc → sim → compare → angles → quiz → takeaway. Repeat `svg`, `calc`, and `angles` as often as the topic needs.

**Drawing `svg` slides: read `ref/svg.md` first.** Raw SVG, kit classes only, captions in `steps`.

## Simulation (`sim`)
- `controls`: `[{"name":"n","label":"cells (n)","min":5,"max":200,"step":5,"value":40}]`
- `js` is the body of `function(ctx, p, W, H, rng, T)`:
  - `p.<name>` = slider values; `W`, `H` = canvas size; `rng()` = seeded random in [0,1) (the reseed button changes the seed).
  - Colours: `T.ink`, `T.muted`, `T.grid`, `T.bg`, accents `T.c[0..5]`. Font is preset.
- Draw one clear picture that changes when a slider moves. Label axes and show one live number.
- Keep the loop small enough to redraw fast (≤ ~10⁶ operations).

## Size rules
- Title ≤ 6 words. Card text ≤ 30 words. Max 4 notes, 5 flow steps, 6 `svg` steps, 7 `calc` lines, 4 angle cards, 3 quiz cards, 5 takeaway points per slide. More → another slide.
- Every number on a slide must also be right in the chat write-up. Check the arithmetic once.

Full worked example: `examples/bootstrap.json` (renders as is: 2 stepped `svg` scenes, a `calc`, a `sim`, `angles`).
